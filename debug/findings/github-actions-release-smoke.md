# GitHub Actions release verification

- Symptom: the first `v0.2.0` publication run warned that the Node.js 20 action runtime used by `actions/checkout@v4` and `actions/setup-node@v4` was deprecated and being forced onto Node.js 24. The release workflow also had no durable post-publication matrix that exercised the public assets.
- Maintenance impact: a later runner cutoff could break CI or publication independently of the project's supported Node.js version, while a syntactically valid bootstrap could still fail only on one operating system.
- Containment: all workflows pin the current official action releases to immutable commit SHAs. The explicit `node-version: 20.18.0` remains the project runtime under test and is separate from the action implementation runtime.
- Release evidence: the manually dispatched `Release smoke` workflow checks out the exact published tag, downloads the public advisor archive and checksum, then runs the real POSIX bootstrap on macOS and Ubuntu and the real PowerShell bootstrap on Windows from clean runner-local roots.
- First smoke result: `v0.2.0` installed and verified on all three systems, but Windows still returned process exit code 1 after printing success. The installed advisor's ordinary `doctor` intentionally returned nonzero because authentication was absent; PowerShell retained that native `$LASTEXITCODE` after the script separately accepted `installationReady: true`.
- Downstream fix: `v0.2.1` explicitly exits 0 only after archive verification, installation, launcher checks, JSON parsing, and `installationReady: true` have all succeeded. Any earlier exception or native install failure remains nonzero.
- Earlier evidence: the public `v0.2.1` assets passed the release smoke matrix on macOS, Ubuntu, and Windows in [run 33597746696](https://github.com/Stevvven777/sustech-course-advisor/actions/runs/33597746696). A separate Darwin arm64 host download matched both the uploaded checksum and GitHub's recorded asset digest, then passed the packaged suite and read-only live doctor from a fresh user-local root.
- Current evidence: `v0.2.2` and `v0.2.3` each exposed a different Windows-only consumer-layout defect that ordinary source CI did not reproduce; details are in `release-install-dependency-audit.md`. After those fixes, public `v0.2.4` and `v0.2.5` passed the real three-platform installation matrix in runs [33609474779](https://github.com/Stevvven777/sustech-course-advisor/actions/runs/33609474779) and [33618920876](https://github.com/Stevvven777/sustech-course-advisor/actions/runs/33618920876). Public `v0.2.8` passed fresh macOS, Ubuntu, and Windows bootstrap installs in [run 33643245686](https://github.com/Stevvven777/sustech-course-advisor/actions/runs/33643245686): the separate version-resolution job checked the workflow revision against the requested 0.2.8 version, while each installation job checked out the exact v0.2.8 tag, verified its package version, and installed the checksummed public asset. PR #33 and merged-main [CI run 33641789016](https://github.com/Stevvven777/sustech-course-advisor/actions/runs/33641789016) exercised the sibling-bound launcher tests on all three platforms, including a Windows path containing `!` under delayed expansion. The workflow retains bounded, failure-only Windows summaries of the consumer manifest, advisor lock entry, and dependency tree.
- Maintenance rule: run the smoke workflow after every GitHub Release, record failures here or in a new synthetic finding, and update action pins only after checking the official release and commit provenance.
