# Upstream fork CI can wait for maintainer approval

- Symptom: upstream `sustech-cli` PR #8 is mergeable, but its check rollup is empty and GitHub reports `mergeStateStatus: UNSTABLE`.
- Root cause: GitHub created [Actions run 33559383724](https://github.com/wormforce/sustech-cli/actions/runs/33559383724) for head `7ce36b6`, then completed it as `action_required` before creating any jobs. This is a workflow-approval state, not a test conclusion; only an upstream maintainer can start the matrix.
- Local evidence: on the exact PR head and current upstream base `8efad42`, type-checking passed; all 326 tests passed when the existing public-calendar integration source was reachable; the runtime audit found zero vulnerabilities; and the package dry run contained 297 files. Credential-dependent child processes were explicitly disabled, and no personal campus read or mutation was performed.
- Test-environment finding: the existing upstream test `context live supports calendar level and degrades gracefully when credentials are unavailable` still downloads the public SUSTech calendar. A network-restricted run fails that one test with `NETWORK_ERROR`, while the same no-credential command passes when only the public source is reachable. This test predates PR #8 and is not evidence of a credential, selection-contract, or privacy regression.
- Maintenance rule: inspect the Actions run itself before treating an empty check rollup as green or red. For `action_required`, send one precise approval request and wait; do not repeatedly rerun, push no-op commits, or claim CI passed. For local restricted-network validation, report the public-source precondition separately from the hermetic unit-test results.
