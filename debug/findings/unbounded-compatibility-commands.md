# Compatibility commands could wait without a deadline

- Symptom: during independent Darwin arm64 validation, direct TIS access did not return before the advisor's ten-second doctor boundary. Reviewing the adjacent compatibility paths showed that `init`, `refresh`, and exact `preview` called the upstream CLI without any timeout when no workflow-specific budget was present.
- Safety impact: a stalled campus service, credential helper, DNS route, or proxy could leave first-use setup or a read-only operation waiting indefinitely. An operator might interrupt and retry without knowing whether the prior stage completed; preview itself is non-mutating, but uncertain control flow near selection operations deserves a fail-closed boundary.
- Downstream containment: `runSustech` now applies a ten-second default to every child process and retains explicit shorter or workflow-budgeted timeouts. Guided init catches the bounded failure and proceeds without inferred personal data; refresh and preview fail with `COMMAND_TIMEOUT`, write no success artifact, perform no automatic retry, and never invoke a campus mutation.
- Network evidence: on the validation host, a no-credential HEAD request to TIS timed out over the advisor's default direct route but returned HTTP 200 through the explicitly inherited local proxy. A single inherited-proxy live doctor then passed in 1.744 seconds with Keychain status ready. The proxy mode was process-scoped and not persisted.
- Test evidence: an independent candidate run started a helper that would wait for 60 seconds; the new default terminated it after 10.007 seconds with stable `COMMAND_TIMEOUT`. A real proxied degree-progress refresh reached the same boundary, logged only `tis degree progress --json`, emitted no success output, and left the mode-`0600` Profile byte-for-byte unchanged. The synthetic success path changed only `refreshedAt`. The suite also locks the default boundary at ten seconds and covers bounded doctor, live workflow, no-write preview, and cached/render-only no-campus behavior on macOS, Ubuntu, and Windows CI.
- Upstream owner: `Stevvven777/sustech-course-advisor`; this is downstream orchestration and does not require an upstream protocol change.
- Maintenance rule: make bounded execution the helper default so a newly added call site cannot accidentally become unbounded. Preserve the stricter total workflow budget, never retry a selection-adjacent timeout automatically, and use one bounded route comparison only after repeated direct timeouts.
